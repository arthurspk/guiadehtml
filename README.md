## :dart: O guia para alavancar a sua carreira

> HTML (HyperText Markup Language) é a linguagem de marcação que estrutura todo o conteúdo da web: todo site, toda aplicação e até e-mail HTML começam com ela. Mantida oficialmente pelo WHATWG (o "HTML Living Standard") e documentada pela Mozilla (MDN) e pelo W3C, é normalmente o primeiro passo de quem quer entrar em front-end, acessibilidade, mobile híbrido ou e-mail marketing. Este guia reúne roadmap, cursos gratuitos e pagos, documentação oficial, livros, canais, ferramentas, desafios práticos e um capítulo sobre como usar IA para aprender e trabalhar com HTML — tudo verificado e organizado para quem está começando do zero até quem quer revisar semântica, formulários e acessibilidade modernas.

## 🗺️ Roadmap

- [roadmap.sh — Frontend Roadmap](https://roadmap.sh/frontend) — Roadmap visual e interativo da comunidade, com HTML como primeiro passo de toda trilha de front-end.
- [MDN — Aprenda desenvolvimento web](https://developer.mozilla.org/pt-BR/docs/Learn) — Trilha oficial da Mozilla, do zero até tópicos avançados, começando por HTML.
- [web.dev — Learn HTML](https://web.dev/learn/html) — Curso estruturado do Google em módulos curtos, do primeiro documento HTML à semântica avançada.

**Trilha resumida** (siga na ordem; cada etapa tem recursos nas seções abaixo):

1. **Estrutura básica** — `<!DOCTYPE html>`, `<html>`, `<head>`, `<body>`, a anatomia de um documento HTML.
2. **Texto e listas** — títulos (`h1`–`h6`), parágrafos, ênfase, listas ordenadas e não ordenadas.
3. **Links e navegação** — `<a>`, caminhos relativos e absolutos, âncoras internas.
4. **Semântica** — `header`, `nav`, `main`, `section`, `article`, `aside`, `footer`: por que a tag certa importa.
5. **Mídia** — imagens, `<picture>`, áudio e vídeo, atributos de acessibilidade (`alt`, legendas).
6. **Tabelas e formulários** — estruturar dados tabulares e coletar informação do usuário corretamente.
7. **Acessibilidade** — landmarks ARIA, ordem de leitura, formulários acessíveis.
8. **Integração** — como o HTML se conecta a CSS e JavaScript para virar uma página completa.

## 🚀 Por onde começar

1. **Instale o ambiente:** um navegador atualizado e o [Visual Studio Code](https://code.visualstudio.com/).
2. **Leia a introdução oficial** em [MDN — Aprenda HTML](https://developer.mozilla.org/pt-BR/docs/Learn/HTML).
3. **Faça um curso rápido gratuito:** [Curso em Vídeo — HTML5](https://www.cursoemvideo.com/curso/html5/) (PT-BR) ou [HTML Crash Course](https://www.youtube.com/watch?v=UB1O30fR-EE) (🇺🇸).
4. **Pratique a sintaxe** escrevendo e salvando arquivos `.html` localmente, abrindo direto no navegador.
5. **Aprenda semântica e acessibilidade** com o [web.dev — Learn HTML](https://web.dev/learn/html).
6. **Valide seu código** no [W3C Markup Validation Service](https://validator.w3.org/) sempre que terminar uma página.
7. **Construa e publique um projeto** no [GitHub Pages](https://pages.github.com/): um currículo, um portfólio ou a réplica de um site simples.
8. **Avance para CSS** para estilizar o que você já sabe estruturar.

Seu primeiro documento em 30 segundos:

```html
<!DOCTYPE html>
<html lang="pt-BR">
<head>
  <meta charset="UTF-8">
  <title>Minha primeira página</title>
</head>
<body>
  <h1>Olá, Guia Dev Brasil!</h1>
  <p>Este é o meu primeiro documento HTML.</p>
</body>
</html>
```

Salve como `index.html` e abra no navegador — pronto, seu primeiro site está no ar (localmente).

## 🛠️ Ferramentas

> Editar e testar

- [Visual Studio Code](https://code.visualstudio.com/) — Editor gratuito mais usado para desenvolvimento web, com suporte nativo a HTML.
- [CodeSandbox](https://codesandbox.io/) — Ambiente de desenvolvimento online para testar HTML, CSS e JS sem instalar nada.
- [StackBlitz](https://stackblitz.com/) — IDE completo no navegador, ótimo para protótipos rápidos em HTML.
- [Emmet](https://emmet.io/) — Abreviações que aceleram a escrita de HTML (já incluído no VS Code).
- [Live Server (extensão VS Code)](https://marketplace.visualstudio.com/items?itemName=ritwickdey.LiveServer) — Recarrega a página automaticamente a cada alteração no HTML salvo.
- [Chrome DevTools](https://developer.chrome.com/docs/devtools) — Ferramentas do navegador para inspecionar, editar e depurar HTML ao vivo.

> Validar e verificar qualidade

- [W3C Markup Validation Service](https://validator.w3.org/) — Verifica se o seu HTML segue a especificação oficial e aponta erros de marcação.
- [W3C CSS Validator](https://jigsaw.w3.org/css-validator/) — Validador oficial de CSS, útil para conferir o estilo aplicado ao HTML.
- [WAVE Web Accessibility Evaluation Tool](https://wave.webaim.org/) — Analisa uma página HTML e aponta problemas de acessibilidade direto no navegador.
- [Lighthouse](https://developer.chrome.com/docs/lighthouse/overview) — Auditoria automática de performance, acessibilidade e boas práticas de HTML.
- [Prettier](https://prettier.io/) — Formatador automático de código, incluindo HTML, para manter um padrão consistente.

> Publicar

- [GitHub Pages](https://pages.github.com/) — Publique um site em HTML puro gratuitamente direto de um repositório do GitHub.
- [Netlify](https://www.netlify.com/) — Hospedagem gratuita para sites estáticos em HTML, com deploy automático.
- [Vercel](https://vercel.com/) — Plataforma de hospedagem e deploy, também usada para publicar sites estáticos em HTML.

## 🤖 IA na prática

HTML é uma linguagem declarativa e verbosa — exatamente o tipo de código onde um assistente de IA economiza mais tempo. Mas ela também é fácil de "parecer certa" e estar semanticamente errada, então o olho humano continua essencial.

**Para aprender**
- Peça para a IA **explicar por que usar `<section>` em vez de `<div>`** em um trecho específico do seu código — e peça um contraexemplo de uso incorreto.
- Cole um HTML seu e peça uma **revisão de acessibilidade**: falta de `alt`, ordem de heading errada, formulário sem `<label>`.
- Peça **exercícios com gabarito** sobre um tópico específico (tabelas, formulários, elementos semânticos) para praticar sem copiar e colar.
- Peça para transformar uma lista de requisitos ("preciso de um cabeçalho, menu, três seções e rodapé") em um esqueleto de HTML semântico, e depois explique cada tag escolhida.

**Para trabalhar**
- Use [GitHub Copilot](https://github.com/features/copilot), [Cursor](https://cursor.com/) ou [Claude Code](https://code.claude.com/docs/en/overview) para gerar a estrutura inicial de uma página, formulários completos com validação nativa (`required`, `pattern`, `type="email"`) e blocos de acessibilidade (ARIA, `alt`, `label`).
- Use o [v0](https://v0.dev/) para gerar rapidamente o HTML/CSS de uma interface a partir de uma descrição em texto — e revise antes de usar em produção.
- Depois de aceitar uma sugestão, **valide sempre** no [W3C Markup Validation Service](https://validator.w3.org/) e confira a acessibilidade no [WAVE](https://wave.webaim.org/).

**Limites e boas práticas**
- IA tende a abusar de `<div>` genéricas em vez de tags semânticas — sempre revise se `header`, `nav`, `main`, `section` e `footer` fazem mais sentido.
- Ela frequentemente **esquece atributos de acessibilidade** (`alt`, `label`, `aria-*`); nunca aceite um formulário ou imagem gerados por IA sem checar isso manualmente.
- Não cole código com dados de clientes ou informações internas da empresa sem verificar a política do seu time.
- Entenda cada tag que você aceita: em entrevista técnica e em produção, o código é seu.

**Ferramentas de IA citadas acima**

- [GitHub Copilot](https://github.com/features/copilot) — Autocompleta tags, atributos e estruturas HTML inteiras a partir de um comentário.
- [Cursor](https://cursor.com/) — Editor com IA integrada, útil para gerar e refatorar páginas HTML completas.
- [Claude Code](https://code.claude.com/docs/en/overview) — Agente de código no terminal: cria, revisa e corrige HTML e acessibilidade em lote.
- [v0 by Vercel](https://v0.dev/) — Gera interfaces completas (HTML/CSS/componentes) a partir de uma descrição em texto.
